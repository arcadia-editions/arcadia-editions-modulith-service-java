# P-01 testGetOrder_400 requests a path no route serves

status: open
found by: T-04, implementer (claude sonnet), 2026-11-12
flow: place-order-flow
blocks: T-04

## Problem
[orders-checkout-openapi.yml:73](../../../arcadia-editions-modulith-api/orders-checkout-openapi.yml#L73) declares
`400 Invalid request` for `GET /orders/{id}` (id integer int64). The generated
`OrdersCheckoutApiIntegrationTest.testGetOrder_400` calls it with `id = ""`, i.e. `GET /api/orders/`. That path
matches no route (Spring 7 no trailing-slash match), so the answer is 404 NoResourceFoundException, never 400.
No ZDL/ZFL line says an empty or non-numeric id is a 400, nor what a missing order returns (contract has no 404).

## Evidence
`mvn test -Dtest='OrdersCheckoutApiIntegrationTest#testGetOrder_400'` with the problem-details handler in place:
`Status expected:<400 BAD_REQUEST> but was:<404 NOT_FOUND>`.

## Options
- A: the test sends a non-numeric id (`abc`); handler maps MethodArgumentTypeMismatchException to 400 problem detail.
  Changes: the test (generated-once, approved baseline), one handler; no model change.
- B: drop the 400 response from the contract and the test (empty id is a 404).
  Changes: openapi, regenerated test.
- C: handler maps NoResourceFoundException on `/api/orders/` to 400. Hack; not recommended.

Recommendation: A.
